# SecuFerry-OS V2.0 核心架构与设计说明书

## 一、 核心架构分层图 (System Stack)

整个系统自下而上分为 3 层。固件层全面采用**刚性单向依赖原则**与**代码级逆向清净设计**（全固件不含任何解密逻辑），以极简的体积换取绝对的物理隔离安全。

### Layer 3: 应用状态机与双向协议层 (Application Layer)

* **全生命周期主控状态机**：内核的“刚性轨道”。严格控制系统在 `初始化(INIT)` -> `任务接收(TASK_ASSIGN)` -> `现场读任务凭证(READ_TASK)` -> `加密落盘(DATA_PULLING)` -> `读特权挑战(READ_SHAKE)` -> `纯密文泵出(DATA_PUMP)` -> `异常死锁(PANIC)` 之间执行不可逆的单向流转。
* **USB HID 双向协议解析器 (`parse_terminal_cmd`)**：无状态轻量级解析器。完整映射并调度全套受控指令集：`0x00(写任务)`、`0x01(读任务)`、`0x02(写数据)`、`0x09(读握手挑战)`、`0x0A(读密文流)`。
* **LED 视觉映射驱动**：将复杂的双向握手内核状态实时翻译为单色/组合闪烁信号，引导执行人员进行全盲盒物理转运。

### Layer 2: 安全存储与单向加密中间件层 (Secure Storage Layer)

* **硬件级单向加密内核 (`aes_encrypt_raw`)**：基于高效的 AES-256 流式加密算法，在 SRAM 缓冲区内对流入的数据块进行实时原位（In-place）加密。**代码层彻底阉割删除 `aes_decrypt`（解密）函数**，使 U 盘在物理上丧失反向还原明文的能力。
* **物理扇区双向管理器 (`sd_raw_write_sector` / `sd_raw_read_sector`)**：接管物理 Micro SD 卡，摒弃传统的 FAT32/NTFS 文件系统，强行划分出 **Sector 1024（任务暗号舱）** 与 **Sector 1025+（密文数据胶囊区）** 进行底层裸块硬写与特权回读。

### Layer 1: 裸金属硬件驱动层 (Bare-metal BSP)

* **Custom HID 寄存器驱动**：手写寄存器配置的 STM32F1 原生 USB 设备驱动。开辟独占式硬件双向缓冲区 `Rx_Buffer` / `Tx_Buffer`，干掉通用 HAL 库，将攻击面缩减至极限。
* **SPI1 物理总线驱动**：高可靠裸金属 SPI 驱动，提供对 SD 卡物理扇区绝对受控的刚性读写时序。

## 二、 SD卡物理扇区隐写与存储隔离视图 (Memory & Storage Map)

系统摒弃 MBR 分区表，将介质化为“物理级扇区隐写墙”。两端上位机与工控机在不同阶段拥有绝对对立的物理访问权限。

```text
===================================================================================
|             32GB 工业级 Micro SD 卡 物理扇区划分与双向控制视图 (无标准文件系统)      |
===================================================================================
  Sector 0                            Sector 1024         Sector 1025 ~ End
+------------------------------------+---------------+----------------------------+
| 区域 A: 盲区/伪装区 (随机噪声)       | 区域 B:           | 区域 C:                    |
| (物理地址: 前 512 KB 区域)          | 任务与管理暗号舱 | 纯密文数据胶囊区           |
|------------------------------------+---------------+----------------------------|
| * 状态: 操作系统无法解析            | * 状态: 密文  | * 状态: AES-256 密文数据流  |
| * 表现: Windows提示无法识别，直接   | - 存放密网签发 | - 工控机日志经 F1 芯片实时 |
|   强制弹窗【磁盘未格式化】          |   的任务令牌与|   原位加密后，连续打入这些  |
|   从底层致盲外部操作系统。         |   管理特权密钥|   裸扇区，不支持芯片内解密。|
+------------------------------------+---------------+----------------------------+
                  ▲                          ▲                      ▲
                  │                          │                      │
                  │        【0x00写任务】     │                      │
                  ├─ Phase 0: 密网下发令牌 ───+                      │
                  │        【0x01读任务】     │                      │
                  ├─ Phase 1: 工控网Agent校验 ─+                      │
                  │        【0x02加密落盘】                          │
                  └─ Phase 1: 工控明文实时打入 ───────────────────────+
                  │        【0x09/0x0A特权抽水】                      │
                  └─ Phase 3: 密网总部全盘泵出 ───────────────────────+

```

### 🔒 物理级权限制衡逻辑

1. **工控现场（Phase 1）**：允许调用驱动读取 Sector 1024 进行任务核对，允许向 Sector 1025+ 流式写入，**但在指令集与固件代码层面被死锁，绝对无法读取 Sector 1025+ 的任何数据**。即便木马劫持了工控机，也无法回读已写入的机密。
2. **转运途中（Phase 2）**：由于没有文件系统和分区表，一旦丢失，任何人通过读卡器提取物理扇区，得到的也只是 Sector 1024 的随机令牌和 Sector 1025+ 的高熵 AES 密文乱码，无法实施暴力破解。

## 三、 确定性单向事件状态机模型 (State Machine Model)

固件完全摒弃多线程调度，采用基于**硬件中断与状态刚性锁**的确定性单向硬状态机，从根源上杜绝竞态条件与越界漏洞。

```text
        (设备上电/自检)
               │
               ▼
      +-----------------+
      |   STATE_INIT    | (🔵 蓝灯常亮：硬件自检，初始化物理 SPI 与 USB 通信)
      +-----------------+
               │
               ▼
      +-----------------+         【0x00: CMD_WRITE_TASK】
      |   STATE_IDLE    | (🔵 蓝灯慢闪：空白态，等待密网总部下发任务授权)
      +-----------------+
               │ ── 触发函数: generate_task_token() -> sd_raw_write_sector(1024)
               ▼
      +-----------------+
      | STATE_ASSIGNED  | (🟢 绿灯慢闪：任务锁死态，具备合法身份，允许带往现场)
      +-----------------+
               │
               ├─►【0x01: CMD_READ_TASK】─► 触发函数: read_task_token() -> 吐出扇区1024校验
               │
               ▼ 【0x02: CMD_WRITE_DATA】(verify_task_policy()校验通过，解锁数据灌入)
      +-----------------+
      |  STATE_PULLING  | (🔵🟢 蓝绿交替爆闪：push_raw_data()流式推流，aes_encrypt_raw()原位加密)
      +-----------------+
               │ 
               ▼ (收到工控机 Agent 发送的 EOF 终止符 或 物理强行拔出)
      +-----------------+
      |   STATE_LOCK    | (🟡 黄灯常亮：数据安全封仓，彻底关闭 0x02 写入通道，软注销电气连接)
      +-----------------+
               │
               ▼ 【0x09: CMD_READ_SHAKE】(插回密网，下发管理挑战码)
      +-----------------+
      |STATE_READ_ALLOW | (🟢 绿灯爆闪：sec_audit_packet()挑战成功，解锁底层回读)
      +-----------------+
               │
               ├─►【0x0A: CMD_READ_DATA】─► 触发函数: sd_raw_read_sector() -> 纯密文盲泵给Master
               │
               ▼ (回收完毕 / 遭遇非法暴力探测 / 物理超温)
      +-----------------+
      |STATE_CORE_PANIC | (🔴 红灯爆闪) ── 强行 memset_s 清空 SRAM 核心缓冲区与 AES 密钥
      +-----------------+

```

## 四、 零拷贝双向数据流管线 (Zero-Copy Data Pipeline)

受限于 STM32F1 极度吃紧的 20KB SRAM，系统抛弃了多层内存拷贝，设计了写入（加密落盘）**与**泵出（无解密回读）双向零拷贝硬管线：

### 1. 明文流加密落盘管线（工控网现场 ── Phase 1）

明文数据进入芯片后，在同一片物理内存上瞬间完成“明文 -> 密文”的原位异变，随即拍死到 SD 卡中。

```text
[工控机 Agent: push_raw_data()]
              │ 
              │ ① USB Custom HID 协议 (64字节/包 连续推流指令 0x02)
              ▼
   +----------------------+
   |  USB_FIFO Rx_Buffer  | ───► ② 硬件中断高速直接搬运
   +----------------------+
              │
              ▼
   +----------------------+
   | SRAM: 512B 乒乓缓冲  | ───► ③ 满单扇区触发状态机切换
   +----------------------+
              │
              ▼ [原位改写内存]
   +----------------------+
   |  aes_encrypt_raw()   | ───► ④ 调用固化根密钥，直接在原 SRAM 地址擦写覆盖
   +----------------------+
              │
              ▼ [明文瞬间化为密文]
   +----------------------+
   |  sd_raw_write_sector | ───► ⑤ SPI1 总线单向推流落盘至 Sector 1025 ~ End
   +----------------------+
              │
              ▼
    【 ⑥ 阅后即焚：sd_raw_write_sector 结束瞬间，内核立即执行 memset_s 对该 SRAM 块清零 】

```

### 2. 纯密文物理泵出管线（密网总部 ── Phase 3）

回读时，U 盘单片机不充当任何计算角色，只做纯粹的“物理抽水机”，将乱码原样吐出，解密算力完全由密网主机承担。

```text
  +-----------------------+
  |  SD 卡 Sector 1025+    |
  +-----------------------+
              │
              │ ⑦ Master.exe 发起 0x0A 连续抽取指令
              ▼
  +-----------------------+
  |  sd_raw_read_sector() | ───► ⑧ SPI1 驱动直接读取原始密文，不经过任何解密逻辑
  +-----------------------+
              │
              ▼ [零拷贝直接移交]
  +-----------------------+
  |  USB_FIFO Tx_Buffer   | ───► ⑨ 经由 USB 总线将纯密文流泵出给上位机
  +-----------------------+
              │
              ▼
[密网 Master.exe: host_decrypt_file()] ───► ⑩ 密网主机本地内存调用核心密钥解密，完美重构明文日志

```

## 五、 全生命周期核心函数闭环联动说明

### 1. 阶段 0：初始化与任务签发（密网总部）

* `Master.exe` 触发 **`generate_task_token()`** 在主控端本地内存中计算生成今日合法的随机任务授权令，通过包装函数发送 **`0x00 (CMD_WRITE_TASK)`** 指令。
* U 盘固件主循环中的 **`parse_terminal_cmd()`** 捕获 0x00 指令，发现用户态无权写盘，立即触发 **`SVC 0x01`** 强制提权至内核态。
* 内核态安全审计器 **`sec_audit_packet()`** 确认当前状态为 `STATE_IDLE`，核对包结构后调用底层驱动 **`sd_raw_write_sector(1024)`**，将任务令牌锁死在任务舱，状态机闭锁切换至 `STATE_ASSIGNED`。

### 2. 阶段 1：现场鉴权与吸数（工控网现场）

* U 盘插手工控机，`Agent.exe` 触发 **`read_task_token()`**，向 U 盘发出 **`0x01 (CMD_READ_TASK)`** 指令。
* U 盘用户态捕获指令并提权，内核审计器批准，调用底层驱动 **`sd_raw_read_sector(1024)`** 将任务令牌回读并通过 USB 吐回给工控机。
* `Agent.exe` 接收到扇区数据，触发 **`verify_task_policy()`**。本地内存动态解析令牌成功（确认时间未过期、目标匹配），工控端软件解锁写入通道。
* `Agent.exe` 启动 **`push_raw_data()`**，高频发送 **`0x02 (CMD_WRITE_DATA)`** 明文流报文。
* U 盘收到指令提权至内核，**`aes_encrypt_raw()`** 动用物理固化根密钥在原 SRAM 缓冲区内进行**原位加密**，随之由 **`sd_raw_write_sector()`** 流式硬写进 `Sector 1025` 以后的存储胶囊区。
* 写入完毕收到 EOF 符或被强行拔出，状态机刚性锁死至 `STATE_LOCK`，注销 USB 电气连接。

### 3. 阶段 3：数据回收与解密还原（密网总部）

* U 盘插回密网主机，`Master.exe` 发出 **`0x09 (CMD_READ_SHAKE)`** 特权挑战码报文。
* U 盘内核 **`sec_audit_packet()`** 动用特权验算挑战码成功，将状态机从 `STATE_LOCK` 单向解禁至 `STATE_READ_ALLOW`（允许回读态）。
* `Master.exe` 收到 ACK 信号，立刻高频盲发 **`0x0A (CMD_READ_DATA)`** 指令。
* U 盘内核调用 **`sd_raw_read_sector()`**，绕过所有文件系统，不进行任何芯片内解密，从 `Sector 1025` 起将纯密文源源不断地经由 FIFO 泵向外侧。
* `Master.exe` 本地内存截获密文流，调用核心解密引擎 **`host_decrypt_file()`**，利用主机端主密钥完成解密拼装，最终在密网桌面上完好无损地还原出目标审计文件。

### 📝 总结：三大流程的函数衔接链条表

| 业务阶段 (Phase) | 触发指令 (Cmd) | 主机端/工具端触发函数 | -> | U 盘用户态函数 | -> | U 盘内核态特权函数 | 最终物理动作 / 存储流向 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **Phase 0 (下发任务)** | `0x00` | `generate_task_token()` | -> | `parse_terminal_cmd()` | -> | `sec_audit_packet()` + `sd_raw_write_sector()` | 令牌刻录至 Sector 1024，状态机切至 `ASSIGNED` |
| **Phase 1 (现场鉴权)** | `0x01` | `read_task_token()` | -> | `parse_terminal_cmd()` | -> | `sec_audit_packet()` + `sd_raw_read_sector()` | 令牌从 Sector 1024 读出并返回给工控机 |
| **Phase 1 (数据写入)** | `0x02` | `push_raw_data()` + `verify_task_policy()` | -> | `parse_terminal_cmd()` | -> | `aes_encrypt_raw()` + `sd_raw_write_sector()` | 明文原位加密，密文硬写至 Sector 1025+ |
| **Phase 3 (读特权握手)** | `0x09` | `CMD_READ_SHAKE` 封装 | -> | `parse_terminal_cmd()` | -> | `sec_audit_packet()` 挑战状态机解锁 | 校验密网高特权挑战码，状态机切至 `READ_ALLOW` |
| **Phase 3 (数据回收)** | `0x0A` | `CMD_READ_DATA` 封装 | -> | `parse_terminal_cmd()` | -> | `sec_audit_packet()` + `sd_raw_read_sector()` | 原始密文不做芯片内解密，直接盲泵给外部主机 |
| **Phase 3 (解密落地)** | 无 | `host_decrypt_file()` | -> | （完全在主机本地内存运行） | -> | （不经过 U 盘任何芯片与固件） | 密网本地主密钥解密，重构并还原出原始日志文件 |
