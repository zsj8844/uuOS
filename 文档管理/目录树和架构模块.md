# SecuFerry-OS V2.0 工程实现与全面测试说明书

为了将 **“Phase 0 密网下发任务”**、**“Phase 1 工控网现场双向鉴权与吸数”** 以及 **“Phase 3 密网特权挑战盲泵”** 的底层架构无缝落地，本说明书对完整工程目录树、核心实现结构、系统状态机枚举以及渐进式验收标准进行了全方位的重构升级。

## 1️⃣ 3_BSP_Drivers (板级底层驱动模块)

本层函数作为无状态的物理原子接口，必须直接操作硬件寄存器，严禁访问任何全局状态机变量。

### 📂 文件：`bsp_usb_hid.c / .h`

#### 1. `void BSP_USB_Init(void)`

* **功能描述**：拉起 STM32 原生 USB 全速外设，初始化 Custom HID 描述符。
* **代码实现骨架**：
```c
void BSP_USB_Init(void) {
    // 1. 开启 USB 物理时钟 (RCC_APB1ENR) 并配置 48MHz 锁相环时钟分频
    // 2. 配置 USB 低功耗/唤醒中断及高低优先级中断向量 (NVIC_Init)
    // 3. 配置端点1 (EP1_IN 用于泵出, EP1_OUT 用于接收)，固定包大小为 64 字节
    // 4. 将 USB 模块从挂起状态唤醒，使能 D+ 引脚上拉电阻，强制总线枚举
}

```

#### 2. `uint8_t BSP_USB_Transmit(uint8_t *pData, uint16_t Len)`

* **功能描述**：强行向 USB 总线盲泵指定长度的密文流。
* **代码实现骨架**：
```c
uint8_t BSP_USB_Transmit(uint8_t *pData, uint16_t Len) {
    if (Len > 64) return 0x01; // 严禁越界溢出
    // 1. 等待上一次硬件发送标志位完成 (EP1_IN_STATUS == FREE)
    // 2. 将 pData 中的数据通过大端模式写入物理分配的 PMA (USB专用数据缓冲区)
    // 3. 设置 EP1_IN 寄存器状态为 VALID，激活硬件物理发送
    return 0x00;
}

```

#### 3. `void USB_LP_CAN1_RX0_IRQHandler(void)`

* **功能描述**：USB 接收中断服务程序。物理硬件一旦捕获外部下当下发的数据包，立即将其无延迟搬运至环形接收区。
* **代码实现骨架**：
```c
void USB_LP_CAN1_RX0_IRQHandler(void) {
    uint8_t tmp_buf[64];
    if (Read_EP1_OUT_PMA(tmp_buf) == 64) {
        // 刚性闭锁：直接呼叫非特权级的协议解析器，严禁执行本地复杂逻辑
        parse_terminal_cmd(tmp_buf); 
    }
    Clear_USB_INT_Flag(); // 清除硬件中断标志位
}

```

### 📂 文件：`bsp_spi_sd.c / .h`

#### 1. `uint8_t SD_Card_SelfTest(void)`

* **功能描述**：上电时对物理 Micro SD 卡执行硬件握手与健康度自检。
* **内部逻辑**：发送 `CMD0` 复位卡 $\rightarrow$ 发送 `CMD8` 校验物理电压 $\rightarrow$ 发送 `ACMD41` 激活卡。若全部应答正确则返回 `SD_OK`，否则返回 `SD_ERROR` 触发系统红灯爆闪。

#### 2. `uint8_t SD_WriteSector(uint32_t SectorAddr, uint8_t *pBuffer)`

* **功能描述**：物理裸块写单扇区函数。无视文件系统，直接将 512 字节拍入物理磁道。
* **代码实现骨架**：
```c
uint8_t SD_WriteSector(uint32_t SectorAddr, uint8_t *pBuffer) {
    // 1. 拉低片选引脚 (PA4 = 0)，强行独占 SPI1 总线
    // 2. 发送物理写单块指令 CMD24 (参数为 SectorAddr)
    // 3. 阻塞等待 SD 卡返回 0x00 (允许写入应答)
    // 4. 发送数据起始令牌 0xFE，紧接着流式传送 512 字节数据
    // 5. 发送 2 字节虚拟 CRC16 校验码
    // 6. 轮询等待 SD 卡内部 busy 状态解除，拉高片选 (PA4 = 1)
    return SD_OK;
}

```
#### 3. `uint8_t SD_ReadSector(uint32_t SectorAddr, uint8_t *pBuffer)`

* **功能描述**：物理裸块读单扇区函数。
* **内部逻辑**：拉低 CS $\rightarrow$ 发送 `CMD17` (读单块) $\rightarrow$ 等待 `0xFE` 令牌 $\rightarrow$ 硬件接收 512 字节灌入 `pBuffer` $\rightarrow$ 拉高 CS。

## 2️⃣ 2_Secure_Storage (安全存储与单向加密模块)

该模块的所有写盘和加密函数必须通过 **`SVC_Handler`** 提权进入芯片内核态运行，任何用户态代码直接调用本层均会抛出硬件异常。

### 📂 文件：`sec_crypto.c / .h`

#### 1. `static void aes_encrypt_raw(uint8_t *pBuffer512)`

* **功能描述**：AES-256 流式原位加密引擎。
* **刚性安全约束**：**本文件内绝对禁止出现 `aes_decrypt` 函数！**
* **代码实现骨架**：
```c
static const uint8_t g_RootKey[32] = { /* 受 RDP Level 2 锁死的 256 位固化根密钥 */ };

static void aes_encrypt_raw(uint8_t *pBuffer512) {
    // 采用流式（如 CBC 或 CTR 模式，此处以 16 字节为一个对齐块，连续迭代 32 次）
    for(int i = 0; i < 512; i += 16) {
        // 对 pBuffer512[i] ~ pBuffer512[i+15] 进行原地异或与混淆矩阵运算
        AES_256_Encrypt_Block(&pBuffer512[i], g_RootKey); 
        // 💥 注意：直接改写原 SRAM 地址上的内容，不使用中间临时变量
    }
}

```
---

### 📂 文件：`sec_raw_storage.c / .h`

#### 1. `uint8_t Sec_WriteTaskToken(uint8_t *pToken)`

* **功能描述**：安全限制写任务令牌。
* **内部逻辑**：由 SVC 中断服务程序派生调用，直接强行将 512 字节的任务令牌写入固定位置：`SD_WriteSector(1024, pToken)`。

#### 2. `uint8_t Sec_ReadTaskToken(uint8_t *pToken)`

* **功能描述**：安全限制读任务令牌。
* **内部逻辑**：直接呼叫 `SD_ReadSector(1024, pToken)`。

#### 3. `uint8_t Sec_PushEncryptedData(uint32_t Offset, uint8_t *pChunk512)`

* **功能描述**：**【核心加密管线】**。接收明文，内存就地原位加密，拍死落盘，内存清零。
* **代码实现骨架**：
```c
uint8_t Sec_PushEncryptedData(uint32_t Offset, uint8_t *pChunk512) {
    uint32_t target_sector = 1025 + Offset;

    // 1. 物理边界安全审计
    if (target_sector < 1025) {
        return STORAGE_ERR_BOUNDARY; // 严禁越界破坏任务舱
    }

    // 2. 原位流式加密：明文瞬间化为高熵密文
    aes_encrypt_raw(pChunk512);

    // 3. 物理裸块落盘
    uint8_t res = SD_WriteSector(target_sector, pChunk512);

    // 4. 🔒 阅后即焚：写盘结束，无论成功与否，立刻物理粉碎 SRAM 缓冲
    memset_s(pChunk512, 0, 512); 

    return res;
}

```
---

### 📂 核心硬隔离中转入口：`stm32f10x_it.c` 中的 `SVC_Handler`

* **功能描述**：ARM 汇编层提权硬闸门。解析应用层发出的汇编指令 `SVC 0x01`，实现用户态向内核态的转换。
* **实现逻辑**：
```c
void __attribute__((naked)) SVC_Handler(void) {
    __asm volatile (
        "TST LR, #4\n"              // 检查当前使用的是哪个堆栈指针 (PSP 或 MSP)
        "ITE EQ\n"
        "MRSEQ R0, MSP\n"
        "MRSNE R0, PSP\n"           // 获取堆栈指针
        "LDR R1, [R0, #24]\n"       // 从栈帧中提取 PC 指针地址
        "LDRB R1, [R1, #-2]\n"      // 读取 SVC 指令低 8 位，获取中断调用号
        "CMP R1, #0x01\n"           // 如果调用号为 0x01，判定为安全存储提权申请
        "BEQ SVC_Secure_Route\n"
        "BX LR\n"
    );
}

void SVC_Secure_Route(uint32_t *args) {
    // 从 args[0], args[1] 中提取上层传入的参数，安全路由分发至 Sec_PushEncryptedData()
}

```

## 3️⃣ 1_App_Layer (应用层刚性状态机模块)

运行在非特权级用户态，负责对全局状态机 `g_CurrentState` 执行单向推进，并解析 USB 报文指令。

### 📂 文件：`app_usb_proto.c / .h`

#### 1. `void parse_terminal_cmd(uint8_t *pPacket64)`

* **功能描述**：Custom HID 双向指令解析器。对当前系统状态进行刚性硬拦截。
* **代码实现骨架**：
```c
void parse_terminal_cmd(uint8_t *pPacket64) {
    uint8_t cmd = pPacket64[0]; // 提取首字节特征指令码

    switch(cmd) {
        case 0x00: // CMD_WRITE_TASK
            if (g_CurrentState == STATE_IDLE) {
                // 触发 SVC 0x01 内核提权，将 pPacket64 写入 Sector 1024
                if (Sec_Call_SVC_Write(pPacket64) == SD_OK) {
                    g_CurrentState = STATE_ASSIGNED; // 刚性跃迁，无法反转
                }
            }
            break;

        case 0x01: // CMD_READ_TASK
            if (g_CurrentState == STATE_ASSIGNED) {
                uint8_t tx_buf[64];
                Sec_Call_SVC_Read(tx_buf); // 读出任务暗号舱
                BSP_USB_Transmit(tx_buf, 64); // 吐给工控机 Agent 进行校验
            }
            break;

        case 0x02: // CMD_WRITE_DATA
            if (g_CurrentState == STATE_ASSIGNED || g_CurrentState == STATE_PULLING) {
                g_CurrentState = STATE_PULLING; // 强行拉入高速吸数态
                static uint32_t global_offset = 0;
                // 组包：将 64 字节的 HID 包流式拼装进 512 字节的大缓冲区
                // 一旦满 512 字节，立即触发 SVC 提权硬写入：
                // Sec_Call_SVC_PushData(global_offset++, sram_block_512);

                // 💡 如果捕获到包尾 EOF 结束符：
                // g_CurrentState = STATE_LOCK; 触发刚性封仓
            }
            break;

        case 0x09: // CMD_READ_SHAKE (特权管理员挑战)
            if (g_CurrentState == STATE_LOCK) {
                if (verify_task_policy(&pPacket64[1]) == SHAKE_SUCCESS) {
                    g_CurrentState = STATE_READ_ALLOW; // 密码机握手成功，解锁回传
                } else {
                    g_CurrentState = STATE_CORE_PANIC; // 挑战失败，判定木马暴力破解，实施自锁
                }
            }
            break;

        case 0x0A: // CMD_READ_DATA (密网总部高频泵出)
            if (g_CurrentState == STATE_READ_ALLOW) {
                uint8_t tx_密文[64];
                // 顺序从 Sector 1025+ 读出密文块，不经过任何解密逻辑，直接盲泵
                // Sec_Call_SVC_Read_Raw_密文(tx_密文);
                BSP_USB_Transmit(tx_密文, 64);
            }
            break;

        default:
            // 捕获到未知非法或恶意变异指令，直接抛向死锁保护
            g_CurrentState = STATE_CORE_PANIC;
            break;
    }
}

```

## 三、 模块依赖关系 (Dependency Graph)

为了保证高层安全策略的刚性约束，杜绝循环依赖和死锁隐患，系统各层级严格遵循**自顶向下的单向依赖与调用原则**：

```text
   ┌──────────────────────────────────────────────────────────┐
   │               1_App_Layer (应用层状态机)                 │
   │  [main.c] -> [app_fsm.c] -> [app_usb_proto.c (0x00-0x0A)]│
   └───────────────────────────┬──────────────────────────────┘
                               │
                               ▼ (单向调用，禁止反向 include)
   ┌──────────────────────────────────────────────────────────┐
   │             2_Secure_Storage (安全存储与加密)            │
   │    [sec_crypto.c (原位加密)] -> [sec_raw_storage.c]      │
   └───────────────────────────┬──────────────────────────────┘
                               │
                               ▼ (单向驱动，保持绝对无状态)
   ┌──────────────────────────────────────────────────────────┐
   │               3_BSP_Drivers (板级硬件驱动)               │
   │       [bsp_usb_hid.c]  [bsp_spi_sd.c]  [bsp_led_wdg.c]   │
   └──────────────────────────────────────────────────────────┘

```

* **安全红线**：`1_App_Layer` 绝不能跳过 `2_Secure_Storage` 直接去呼叫物理读写；底层的 `3_BSP_Drivers` 作为系统的物理基石，**绝对禁止** `#include` 任何上层业务、状态或协议相关的头文件。

## 四、 步步为营的渐进式测试验收标准 (Testing Strategy)

为了彻底降低联调痛苦指数，开发与验收必须分为以下三个具有严格里程碑的阶段：

### 📈 Stage 1: 底层原子驱动与“存储隐写墙”物理验收

* **测试方法**：在 `main.c` 刚刚初始化完成后，不拉起 USB 堆栈，直接在代码中硬编码调用底层驱动 `SD_WriteSector(1024, "TASK_TOKEN_TEST_001")` 和 `SD_WriteSector(1025, "RAW_DATA_TEST_002")`。
* **期望现象**：
1. 通过仿真器在线查看，驱动函数均返回成功状态码（`SD_OK`）。
2. **物理硬验证（核心）**：将 U 盘从开发板拔下，插入普通的 Windows/Linux 办公电脑。操作系统必须**无法识别文件系统**，并立刻弹出强烈的警告：`“磁盘未格式化，是否格式化？”`（证明全卡无分区表，隐写致盲成功）。
3. 使用底层扇区查看工具（如 WinHex 或 DiskGenius）直接打开该物理驱动器，跳跃到物理第 1024 扇区和 1025 扇区，能清晰看到硬写进去的明文字符串。


* **验收标准**：底层物理扇区非标裸块读写机制完全打通。

### 📈 Stage 2: 密网下发与工控现场双向状态机联调 (Phase 0 & 1 联动)

* **测试方法**：擦除 SD 卡，复位 U 盘。接入密网端 Python 测试脚本，随后转运至工控网端 Python 采集脚本。
* **期望现象**：
1. **下发测试**：设备上电进入 `STATE_IDLE`（蓝灯慢闪）。密网脚本通过 USB 发送 **`0x00`** 指令并附带任务令牌。设备触发 `SVC 0x01` 提权，内核调用 `sd_raw_write_sector(1024)` 录入成功。状态机**单向跃迁**为 `STATE_ASSIGNED`（绿灯慢闪）。
2. **现场鉴权测试**：将处于 `STATE_ASSIGNED` 的设备插入工控机。工控端 Agent 盲发 **`0x01`** 读任务指令。设备内核调用 `sd_raw_read_sector(1024)` 将任务令牌吐回给工控机。Agent 在本地通过 `verify_task_policy()` 动态验算通过。
3. **数据加灌测试**：工控机 Agent 触发 `push_raw_data()`，高频盲发 **`0x02`** 明文流。设备状态机瞬间切入 `STATE_PULLING`（蓝绿交替爆闪）。此时在内存中用 WinHex 观察，SRAM 缓冲区的明文在 `aes_encrypt_raw()` 作用下**原位异变为乱码密文**，并高频拍死在 Sector 1025+ 之后。


* **验收标准**：双向鉴权流控制链条闭环，工控端写回读死锁限制生效。

### 📈 Stage 3: 特权挑战盲泵与上位机软件解密全链路闭环验收 (Phase 3 答辩标准)

* **测试方法**：工控机发送 EOF 或拔出设备，设备转为 `STATE_LOCK`（黄灯常亮，USB 物理层软电气注销）。转运人员将其插回密网总部主控电脑，拉起 `Master.exe` 核心回收引擎。
* **期望现象**：
1. **特权挑战测试**：普通操作系统依然由于弹窗无法读取任何文件。`Master.exe` 通过强行底流通讯发出 **`0x09`** 指令，下发密网根特权挑战码。U 盘内核 `sec_audit_packet()` 动态验算成功，状态机极其严苛地解锁至 `STATE_READ_ALLOW`（绿灯爆闪）。
2. **盲泵密文测试**：`Master.exe` 高频轮询发送 **`0x0A`** 抽取指令。U 盘内核调用 `sd_raw_read_sector()`，**不进行任何解密操作（因为固件中没有解密函数）**，像抽水机一样把 Sector 1025+ 起始的原始密文乱码全量泵出到 USB 总线。此时若用物理逻辑分析仪抓取总线，全链路**皆为高熵乱码密文**。
3. **上位机还原**：密网主机的内存完全截获密文流，本地调用 `host_decrypt_file()` 动用主密钥就地解密、对齐、重组，最终在密网桌面上**完美、无损地还原**出最初在工控网采集的原始明文日志文件。


* **验收标准**：数据全生命周期“工控网明文进 $\rightarrow$ U 盘乱码存 $\rightarrow$ 总线密文传 $\rightarrow$ 密网明文出”的盲盒高安全转运流程完美闭环，具备军工级抗物理拆解与抗中间人窃听能力。
