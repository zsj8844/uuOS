SecuFerry-OS V2.0 产品功能特性与硬件清单
一、 系统核心功能特性
1. 外形类似U盘，物理形态小巧
设备外形如大拇指大小，一阶段原生采用 Type-C / USB 接口 直接接入目标工控上位机。硬件引脚和内核驱动层留有高扩展性，二期可在不重构核心逻辑的前提下无缝升级以太网口或工业串口。

2. 在“安全密网端”预制任务（防内鬼与责任精确定位）
摆渡任务的审计路径和安全策略由管理员在安全的密网总部通过 Master.exe 预先设定。系统在 STATE_IDLE 状态下接收 0x00 (CMD_WRITE_TASK) 指令，触发 SVC 0x01 硬件提权，将任务令牌硬写死在 Sector 1024（任务暗号舱） 中。
转运执行人员全程无任何查看、选择或修改数据的权限，其职责仅为物理插拔。通过这种“盲盒机制”，彻底杜绝了执行人员“私自拷贝泄密”的嫌疑。一旦发生数据泄露，可立即精准定位到任务制定者或设备物理丢失责任人。

3. 插入工控机后全自动现场鉴权与“盲盒”吸数
设备内部运行自研双向受控状态机。插入目标工控机后，工控机后台常驻的免安装 Agent.exe 脚本自动盲发 0x01 (CMD_READ_TASK) 指令索要暗号，并在工控本地通过 verify_task_policy() 动态验算通过后，方可解锁写入通道。
随后，Agent 脚本启动 push_raw_data()，高频盲发 0x02 (CMD_WRITE_DATA) 明文流，系统自动切入 STATE_PULLING 状态进行全自动吸数。全过程对现场操作员完全透明，无需任何鼠标点击或文件拖拽。

4. GB级大容量流式原位加密与非标准扇区隐写
为了满足工控机海量日志及系统镜像（1GB ~ 数GB级）的摆渡需求，设备彻底抛弃了标准的文件系统管理（如 FAT32/NTFS），采用非标物理扇区偏移量进行裸块硬写。
流入的明文数据在芯片内部 SRAM 缓冲区直接通过 aes_encrypt_raw() 动用固化根密钥进行原位（In-place）加密。明文瞬间化为密文后，由 sd_raw_write_sector() 连续拍死在 Sector 1025 ~ End（密文数据胶囊区）。

⚠️ 安全红线：固件代码中全面阉割删除了 aes_decrypt() 解密函数，芯片本身在代码级丧失了解密能力。即便设备在转运途中物理丢失并被中间人拆解，插入普通 PC 时，操作系统也会因无分区表而直接弹窗提示【磁盘未格式化，是否格式化】，底层完全致盲。

5. 回到密网总部特权挑战回传与闭环
任务完成后，设备进入 STATE_LOCK 刚性封仓。带回密网总部插入受信任的主控电脑后，Master.exe 必须首先高频盲发 0x09 (CMD_READ_SHAKE) 特权挑战码。
U 盘内核调用 sec_audit_packet() 验算成功后，状态机才极其严苛地解锁至 STATE_READ_ALLOW，允许通过 0x0A (CMD_READ_DATA) 将 Sector 1025+ 的纯密文流像抽水机一样盲泵给上位机。最终由密网主机本地内存调用 host_decrypt_file() 完成软件解密与审计闭环。

6. 杜绝非安全监控下的人为拷贝与勒索交叉感染
全流程数据流由底层硬状态机刚性控制，底层和协议栈坚决不挂载任何标准 USB 大容量存储（MSC）协议（工控机绝不会将其识别为普通 U 盘），彻底断绝了利用 U 盘进行违规拷贝、中间人篡改或工控勒索病毒交叉感染的物理与协议通道。

7. 专注单一安全功能，降低攻击面
系统配置了硬件独立看门狗（IWDG），全固件零动态内存分配（无 malloc/free），彻底杜绝堆溢出漏洞。代码架构由硬性的 C 语言顺序执行体与硬件中断服务程序驱动，极大缩小了被外部漏洞利用的攻击面，确保高质量稳定交付。

二、 物理硬件功能清单（一期开发）
1️⃣ STM32F103 核心主控板（数字大脑）
系统职能：整个摆渡设备的控制核心。负责运行全生命周期单向硬状态机、Custom HID 双向外设驱动、AES-256 原位加密内核以及无文件系统的裸扇区双向管理器。

💡 架构升级校准（关键 peer 提示）：为了防御工控机侧木马通过 USB 漏洞实施远程代码执行（RCE）攻击，一期工程必须引入 ARM Cortex-M3 硬件特权级切换（SVC 闸门）。利用 SVC 0x01 指令将非特权用户态（负责解析 HID 报文的 parse_terminal_cmd）与特权内核态（负责写盘的 sd_raw_write_sector 和负责加密的 aes_encrypt_raw）彻底隔离，构建芯片内的刚性防火墙。

物理特征：基于经典 ARM Cortex-M3 内核（主频 72MHz），大拇指大小的长条形电路板（如经典的“蓝药丸” Blue Pill 升级版），自带 Type-C 接口，两侧预留排针用于后期功能扩展。

购买认准：搜索“STM32F103C8T6 最小系统板 Type-C 版”或“STM32F1 开发板”。

2️⃣ Micro SD (TF) 卡读写模块与工业级存储卡（大容量加密物理存储器）
系统职能：作为设备的“大容量加密保险箱”。工控机传输过来的数据，经主控板实时原位加密成纯密文后，通过高可靠的 SPI1 物理总线，源源不断地直接硬写进存储卡的物理扇区中。

物理特征：标准的 Micro SD 卡 SPI 通信模块，搭配一张 16GB 或 32GB 的高可靠性工业级 TF 存储卡。

购买认准：搜索“TF卡读写模块（SPI接口）” + “工业级 高速 TF 卡”。

3️⃣ ST-Link V2 烧录器（内核调试器）
系统职能：连接开发电脑与 STM32F1 核心板的底层硬件桥梁。用于将状态机代码、SVC 提权中断服务程序烧录进芯片，并利用它进行源码级的 Thread 模式（用户态）与 Handler 模式（内核态）跨越断点调试。

物理特征：外形类似长条形铝合金 U 盘，一端为标准 USB 口插电脑，另一端露出一排排针，通过杜邦线与主控板的 SWD 接口相连。

购买认准：搜索“ST-Link V2 仿真器”或“STLINK 迷你下载器”。

4️⃣ RGB LED 颗粒（全局状态视觉映射驱动）
系统职能：实现设备的“无头/盲盒运行模式”。由于高安全和盲盒逻辑要求设备不带任何屏幕和人机交互界面，系统状态机全生命周期的 7 大状态流转全靠这颗灯进行可视化精确定位：

视觉信号 (LED 灯效)	映射内核状态机 (FerryState_t)	物理/业务阶段含义说明
🟢 绿灯常亮	STATE_INIT	系统就绪，等待 EXE 连接
🔵 蓝灯常亮	STATE_ASSIGNED	任务锁死态，已注入合法暗号 (WriteTask 完成)
🟢 绿灯慢闪	STATE_PULLING	数据已加密落盘 (WriteData 完成)
🟢🔵 青灯常亮	STATE_LOCK	握手等待中，等待密网或工控发起连接
⚪ 白灯常亮	STATE_READ_ALLOW	数据已取出 (ReadData 完成)，全流程闭环
🔴 红灯爆闪	STATE_CORE_PANIC	崩溃死锁态，3 次挑战失败触发自锁
物理特征：带有 4 个引脚的微型模块，能通过底层 GPIO 程序控制调制出红、绿、蓝及组合颜色的光。

购买认准：搜索“RGB LED 模块”或“三色 LED 灯”。

5️⃣ 面包板与高品质杜邦线（原型开发基座）
系统职能：原型机搭建的物理载体。用于在一期开发阶段打通 STM32 主控核心板、TF 卡读写模块、RGB 状态指示灯之间的物理信号线路，方便开发时连接逻辑分析仪进行 Custom HID 总线报文和 SPI 时序信号抓取调试。

购买认准：搜索“8.5x5.5cm 面包板” + "公对母/母对母 杜邦线套装"。

以下工业级物理接口模块在当前一期阶段暂不投入代码编写与驱动堆栈开发，但硬件引脚已做前瞻性预留，后续可在不改变 V2.0 核心状态机轨道的前提下无缝升级：

// W5500 以太网模块（网络接口）：用于直接插入不带 USB 口的工业交换机或网络自动化设备，二期将通过轻量级 TCP/IP 栈和 Modbus-TCP 协议主动抓取网络层审计数据。

// TTL 转 RS485 模块（工业串口接口）：用于直接连接现场的 PLC、变频器等带有 RS485 串口的工业底层硬件，二期将通过 Modbus-RTU 协议读取寄存器数据。
